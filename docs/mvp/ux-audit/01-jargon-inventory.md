# Jargon inventory: words the buyer app shows that a builder or purchasing coordinator would not use

Date: 2026-10-07. Status: audit input for the owner's "too detailed, unclear labels" review. No code or other doc was changed.

Paths are relative to `apps/web/`. Proposed labels are suggestions for wording only, not code changes.

## Method and limits

- Searched `components/`, `app/` and `lib/` (`*.ts`, `*.tsx`) with `grep -rn -i -E` for each candidate term and its plural or variant forms (for example `\b(indicative)\b`, `ex[ _-]?VAT`, `tier[s]?`). Where a row cites `lib/kits/generated/uk/*.json`, the text is template data that the app renders as-is.
- Kept only hits inside text a person can see: JSX text, quoted labels, template literals that reach the page, aria-labels, titles, tooltips, badges, error messages and JSON text. Identifiers, imports, class names, attributes, data keys and comments were dropped. Multi-line JSX prose was found with a second grep and read in context.
- `xN` = approximate number of distinct visible strings that show the term (as a label, message, badge, tooltip or displayed value), counted by hand from the grep output. Treat it as roughly plus or minus 20 percent. It is not a render count. Rows are ordered by `xN`, highest first.
- `Where` lists up to three `file:line` references (the clearest ones), then the total.
- Exact strings are copied from the code. A value filled in at run time is shown as `{x}` or `N`. An ellipsis marks omitted text.
- Not done: no screen rendering, no screenshots, no run of the app. The 8 MB `lib/quote-data/*.json` files were searched only for the examples cited. `partition` appears once in a visible error (`lib/quote/schema.ts:36`) and is not tabled.
