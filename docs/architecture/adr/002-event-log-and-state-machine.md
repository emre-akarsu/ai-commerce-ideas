# ADR-002: Hash-chained append-only event log + explicit state machine
**Status:** accepted. **Context:** spec F8 and R-rules require a complete, tamper-evident audit trail; liability depends on showing who authorised what. **Decision:** every state change is an `Event` with `prev_hash`/`hash`; request state is changed only through the workflow module which emits the event atomically. Payload PII fields are redactable by replacing with a tombstone while keeping the chain verifiable (hash over canonical payload with redaction markers). **Consequences:** no direct status writes anywhere; verification utility in tests. **Alternatives:** full event sourcing (more complexity), Temporal (deferred until job volume justifies).
