# ADR-003: Send-service is the only sender; Approval objects bind to message hash
**Status:** accepted. **Context:** "send only on approval" is not an OAuth property; model output must never trigger an outbound action (red team S-Sec4, S-ENF). **Decision:** a send-service module is the sole holder of mail transport credentials. It accepts `Approval{kind, mime_hash, approver, nonce, expires_at, rule_id?}` where `mime_hash` is the SHA-256 of the exact final message including the footer. It verifies hash, expiry, single-use nonce (or standing-rule limits), recipient allow-list (preferred vendors + registered domains), caps, and appends the non-removable AI footer before hashing. The planner has no import path to the transport. **Consequences:** edits after approval invalidate approval; follow-ups are pre-approved schedules; tests assert refusal without a valid Approval. **Alternatives:** mailbox OAuth with send scope (rejected: not enforceable, IT friction).
